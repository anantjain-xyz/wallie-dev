# Wallie factory — 100-capability implementation matrix

**Every capability has an end-state deliverable, a completion milestone, reusable foundations, prerequisites and a completion proof. None is removed from scope.**

- Read the [implementation plan](factory-implementation-plan.md) for milestone slices, the dependency graph, design rules and release gates.
- `Mxx` is the milestone responsible for full completion, not the first time any part becomes usable. Existing execution/harness/provider foundations are available before their later end-state qualification milestones.
- `Rxx` refers to the plan's [reuse register](factory-implementation-plan.md#reuse-register). Reuse means preserve/extend that owner; it is not a claim that the whole capability already exists.
- Capability prerequisites below cover new work. Existing foundations referenced by `Rxx` can be used immediately. Milestone prerequisites add migration, security, context and integration gates.
- “Foundation exists / Extend / New” preserves the original inventory assessment. The implementation and verification columns specify what still must ship; every row starts **planned**.
- The [machine-readable register](factory-capabilities.json) preserves original descriptions, video timestamps, source links and acceptance criteria alongside these implementation fields.

## Coverage

100 unique IDs: F001–F100. F001–F097 are spoken or shown in the recording; F098–F100 are the explicit open-source distribution extensions. Acceptance criteria are proposed Wallie product behavior, not quotations or claims about Warp's implementation.
